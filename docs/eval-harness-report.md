# 离线护栏评测 (确定性, 无 LLM)

分两档对抗样本：easy=教科书形态(检测器该抓的标准写法)；hard=对抗规避(同义改写/别名简称/隐式时间词/绰号称谓)。

| 指标 | 基线 | 当前残留 | 总召回 | easy 召回 | hard 召回 | 误报 | 对抗/干净 |
|------|------|------|------|------|------|------|------|
| 时间线冲突率 | 100.0% | 50.0% | 50.0% | 100.0% (3) | 0.0% (3) | 0.0% | 6/3 |
| 已销毁道具复活率 | 100.0% | 50.0% | 50.0% | 100.0% (3) | 0.0% (3) | 0.0% | 6/3 |
| 越权知情/剧情泄露率 | 100.0% | 50.0% | 50.0% | 100.0% (3) | 0.0% (3) | 0.0% | 6/3 |
| 角色越权登场率 | 100.0% | 50.0% | 50.0% | 100.0% (3) | 0.0% (3) | 0.0% | 6/3 |
| Controller 重写率(P0 拦截) | 0.0% | 25.0% | - | - | - | - | 全语料 |

说明：「残留」= 违规最终留在正文的比例 = 漏检率(1-总召回)。基线=护栏关时对抗样本 100% 出库。
误报 = 干净样本被错误拦下的比例。Controller 重写率 = 被判 P0 路由到 Reviser 的草稿占比(基线无此拦截=0%)。

**读法**：easy 召回证明护栏接线正确；**hard 召回才是真实强度**——它暴露确定性检测器
(全名/正则匹配)对改写、别名、隐式表达的盲区。hard 掉下来的部分，正是需要 LLM 审计层
(audit 的 future_event_leak LLM 路径)兜底、或把检测器升级为别名/语义匹配的地方。
基线 = 同一批样本在没有该护栏时原样放行的可证下界，非重跑旧 LLM 管线。
