精简后的架构
章纲生成/更新（1次，通常提前完成）
        ↓
本地编译 Chapter Package（0次 LLM）
        ↓
整章正文生成（1次 LLM）
        ↓
本地确定性检查（0次 LLM）
        ↓
综合审计 + 新实体提取 + 接受决策（1次 LLM）
        ↓
通过：自动采纳并更新知识图谱
失败：局部重写（额外1次）
正常情况下，已有章纲后只需要：
第一次：整章正文生成
第二次：综合审计并决定是否接受
RAG、权限过滤、合同生成、状态更新都由程序完成，不调用 AI。
一、章纲阶段一次完成所有规划
生成章纲时，不再只生成三拍，而是一次输出完整章节包：

  "items": [

这份 JSON 同时承担：
章纲
人物选择
道具选择
势力选择
场景流
权限合同
不再额外调用“场景规划 AI”“资源绑定 AI”“权限编译 AI”。
权限编译由程序确定性完成。
二、整章一次生成
不再：
第一拍调用一次
第二拍调用一次
第三拍调用一次
水面稿再调用一次
改成一次生成整章。
模型收到：
当前章节包
已采纳前情
当前人物状态
RAG 检索结果
上一章结尾
文风规则
要求模型按照 scene_flow 自然组织正文。
scene_flow 不是要求“一场一段”，只是告诉模型：
从哪里开始
中间如何推进
最后停在哪里
模型可以自行使用过渡句、时间推进和场景合并，因此不会再有三拍拼接感。
三、RAG 不调用 AI
RAG 完全是本地检索：
当前章节包提供 allowed_entity_ids
        ↓
数据库硬过滤
        ↓
在允许范围内做相似度检索
        ↓
返回人物卡、物品卡、地点环境和已知事实
例如本章允许：
{
  "allowed_entity_ids": [
    "p_chen",
    "p_linwan",
    "obj_phone",
    "obj_ring_image",
    "loc_shop",
    "fac_afterservice"
  ]
}
那么即使搜索词命中“锦澜湾”“程行”，数据库也不会返回它们。
这是程序权限，不需要问 AI。
四、本地检查先挡明显错误
正文生成后先跑零成本检查：
未授权人物
未授权地点
未授权道具
姓名漂移
地址漂移
发明日期
未来章关键词
未授权 canonical fact
道具是否有来源
是否到达当前章出口
是否明显超过当前章出口
如果出现确定性 blocker，可以直接进入局部重写，不必浪费一次审计调用。
五、综合审计只调用一次
把原来的：
文风审计
普通章节审计
scope 审计
留白审计
新实体提取
人工验收
合并成一次 AI 调用。
输出：
{
  "decision": "accept",
  "scores": {
    "scope": 0.98,
    "continuity": 0.91,
    "progress": 0.94,
    "style": 0.87
  },

AI 在这里直接做最终验收。
六、AI 自动接受规则
最终状态由程序结合确定性检查和 AI 决策决定：
if deterministic_blockers:
    status = "blocked"

elif audit.decision == "accept":
    accept_draft()
    commit_entities()
    commit_facts()
    commit_graph_updates()

elif audit.decision == "rewrite":
    rewrite_targets()

else:
    status = "blocked"
不再需要人工点“接受”。
前端可以显示：
AI 已接受
权限检查：通过
连续性：0.91
新增知识图谱节点：物业签收单
但用户仍保留：
撤销采纳
手动退回重写
查看审计依据
AI 决策是默认流程，用户只负责例外干预。
七、局部重写最多一次
审计失败时，不整章重写，只提交：
{
  "paragraphs": [8, 9],
  "problem": "提前写出尸骨位置",
  "instruction": "删除尸骨相关信息，让本章停在签收记录矛盾"
}
调用一次局部编辑模型。
编辑后只重新运行：
本地确定性检查
必要时一次精简复审
如果仍失败，直接 blocked，不无限循环。
最终调用量
已有章纲时
正常路径：
环节	LLM 调用
Chapter Package 编译	0
RAG	0
整章正文	1
确定性检查	0
综合审计、实体提取、接受决策	1
自动采纳和图谱更新	0
合计	2

需要生成章纲时
环节	LLM 调用
生成章纲与资源清单	1
整章正文	1
综合审计与自动接受	1
合计	3

审计失败时
增加一次局部重写，通常总共 3 次。
所以最合适的版本是：
章纲阶段一次把剧情、人物、物品、势力和场景流规划完整；正文整章一次生成；最后一次 AI 同时完成审计、新实体筛选和自动接受。正常写一章只调用两次模型。
